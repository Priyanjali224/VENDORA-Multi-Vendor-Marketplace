# VENDORA Manual Deployment Guide

This guide provides step-by-step instructions for deploying VENDORA to production using MongoDB Atlas, Render (Backend API), and Vercel (Frontend Single Page Application).

> [!IMPORTANT]
> All steps below are designed for manual execution by the engineer. Do not paste live credentials, database passwords, or payment private keys in chat or public repositories.

---

## 1. Local Git & GitHub Setup

1. **Verify Git Remote:**
   ```bash
   git remote -v
   ```
   *Expected: `https://github.com/Priyanjali224/VENDORA-Multi-Vendor-Marketplace.git`*

2. **Push Production Ready Code:**
   ```bash
   git push origin main
   ```

---

## 2. MongoDB Atlas Configuration

1. Create a free shared M0 cluster on [MongoDB Atlas](https://www.mongodb.com/cloud/atlas) in the **Singapore** or nearest region.
2. Under **Database Access**, create a user:
   - Username: `vendora_admin`
   - Password: `<GENERATE_STRONG_PASSWORD>`
   - Database Role: `readWriteAnyDatabase`
3. Under **Network Access**, add IP Access List:
   - Allow Access from Anywhere (`0.0.0.0/0`) so Render dynamic cloud instances can connect.
4. Retrieve Connection String:
   - Click **Connect** -> **Drivers (Node.js)**.
   - Format: `mongodb+srv://vendora_admin:<PASSWORD>@cluster0.xxxxx.mongodb.net/vendora?retryWrites=true&w=majority`
   - **Target Database Name:** Ensure `vendora` is the database name (the backend also enforces `dbName: 'vendora'`).

## 3. Backend Deployment on Render

### Method A: 1-Click Blueprint (Recommended)
1. Log in to [Render](https://dashboard.render.com).
2. Click **New +** -> **Blueprint**.
3. Connect your repository: `Priyanjali224/VENDORA-Multi-Vendor-Marketplace`.
4. Render will read `render.yaml` automatically, configuring the **Singapore** region, service name `vendora-backend`, root directory `backend`, and health check `/health`.
5. Enter the required manual secrets when prompted:
   - `MONGODB_URI`: Your MongoDB Atlas connection string.
   - `CLIENT_URL`: Your Vercel frontend URL (can be filled after frontend is deployed or entered as placeholder).
   - `RAZORPAY_KEY_ID`: Your Razorpay test Key ID (optional in test mode).
   - `RAZORPAY_KEY_SECRET`: Your Razorpay test Key Secret (optional in test mode).

### Method B: Manual Web Service Setup
- **Service Name:** `vendora-backend`
- **Region:** `Singapore`
- **Root Directory:** `backend`
- **Runtime:** `Node`
- **Build Command:** `npm install`
- **Start Command:** `npm start`
- **Health Check Path:** `/health`

## 4. Frontend Deployment on Vercel

1. Log in to [Vercel](https://vercel.com).
2. Click **Add New...** -> **Project**.
3. Import `Priyanjali224/VENDORA-Multi-Vendor-Marketplace` from GitHub.
4. Configure Framework & Root Directory:
   - **Framework Preset:** `Vite`
   - **Root Directory:** Click Edit and select `frontend`.
   - **Build Command:** `npm run build`
   - **Output Directory:** `dist`
5. Configure Environment Variables in Vercel:
   - `VITE_API_URL`: `https://<YOUR-RENDER-BACKEND-URL>.onrender.com/api`
   - `VITE_STORAGE_URL`: `https://<YOUR-RENDER-BACKEND-URL>.onrender.com`
   - `VITE_RAZORPAY_KEY_ID`: `<YOUR-RAZORPAY-KEY-ID>` (or test key)
6. Click **Deploy**.
7. Vercel builds the SPA with client rewrites via `vercel.json` ensuring deep URLs do not 404.

## 5. Post-Deployment Smoke Testing Checklist

1. **Health Check Probe:**  
   Open `https://vendora-backend-xxxx.onrender.com/health` in your browser.  
   Expected JSON response:
   ```json
   {
     "status": "healthy",
     "service": "VENDORA Multi-Vendor Marketplace API",
     "environment": "production",
     "database": "connected"
   }
   ```
2. **Database Auto-Seeding Verification:**  
   On first launch with an empty Atlas database, VENDORA automatically populates the initial admin, vendors, categories, and products.
3. **Authentication Smoke Test:**  
   Log in as Platform Admin (`admin@vendora.com` / `adminPassword123`) and Vendor (`apex@vendora.com` / `vendorPassword123`).
4. **End-to-End Order Flow:**  
   Add items from 2 vendors, apply `VENDORA10`, checkout, and download the generated PDF tax invoice.
